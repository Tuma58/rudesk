# rudesk

Пошаговая установка **личного сервера удалённого доступа RustDesk** на чистый VPS с Debian или Ubuntu.

После установки вы подключаетесь к своим компьютерам через официальный клиент RustDesk, но трафик идёт через **ваш** сервер (не через публичные серверы RustDesk).

Установщик самодостаточный: бинарники `hbbs` и `hbbr` уже лежат в этом репозитории (`vendor/`). Во время установки они **не скачиваются** с чужих сайтов — это защищает от «битых» ссылок в будущем.

---

## Что вам понадобится

1. **VPS** (виртуальный сервер) с ОС:
   - Debian 11 / 12 / 13, или
   - Ubuntu 22.04 / 24.04
2. Доступ по **SSH** (логин `root` или пользователь с `sudo`)
3. Публичный **IP-адрес** сервера (выдаёт хостинг)
4. На домашнем/рабочем ПК — клиент [RustDesk](https://github.com/rustdesk/rustdesk/releases)
5. 10–15 минут и спокойствие 🙂

Архитектура сервера: **x86_64 (amd64)** или **ARM64 (aarch64)**.

Рекомендуемые ресурсы: от 1 vCPU, 512 МБ–1 ГБ RAM, 5+ ГБ диска — для личного использования этого достаточно.

---

## Кратко: одна команда (когда система уже подготовлена)

Если на VPS уже есть `curl` и `tar` (см. шаг 2 ниже), под `root` достаточно:

```bash
curl -fsSL https://github.com/Tuma58/rudesk/archive/refs/heads/main.tar.gz | tar xz && sudo bash rudesk-main/install.sh
```

Дальше отвечайте на вопросы мастера. В конце скрипт покажет **IP/домен** и **Key** для клиента.

Ниже — полный путь для начинающего администратора.

---

## Шаг 1. Войдите на сервер по SSH

На своём компьютере откройте терминал (macOS/Linux) или PowerShell / Windows Terminal.

Пример (подставьте IP своего VPS):

```bash
ssh root@203.0.113.10
```

или, если вход по normallyму пользователю:

```bash
ssh admin@203.0.113.10
```

При первом входе подтвердите fingerprint (`yes`) и введите пароль (символы при вводе не отображаются — это нормально).

Если вы вошли не как `root`, дальше либо используйте `sudo` перед командами, либо:

```bash
sudo -i
```

---

## Шаг 2. Подготовьте «чистый» VPS (обязательные пакеты)

На только что созданном сервере часто **нет** даже `curl` и `tar`. Без них команда установки из интернета не сработает.

Выполните **от root**:

```bash
apt-get update
apt-get install -y curl ca-certificates tar gzip
```

Что это даёт:

| Пакет | Зачем |
|--------|--------|
| `curl` | скачать архив rudesk |
| `ca-certificates` | проверять HTTPS-сертификаты |
| `tar` / `gzip` | распаковать архив |

`install.sh` сам доустановит остальное (DNS-утилиты, openssl, ufw по желанию и т.д.), но **эти четыре пакета нужны уже до запуска** one-liner.

Проверка:

```bash
curl --version
tar --version
```

---

## Шаг 3. Порты: VPS в облаке или сервер за NAT

RustDesk слушает несколько портов. Без доступа к ним с интернета клиенты не подключатся.

| Порт | Протокол | Зачем |
|------|----------|--------|
| **21115** | TCP | проверка типа NAT |
| **21116** | TCP и **UDP** | регистрация устройств, hole punching |
| **21117** | TCP | relay (если прямое соединение не удалось) |
| 21118–21119 | TCP | web-клиент (для обычного ПК-клиента можно не открывать) |

**Минимум:** TCP **21115–21117** и UDP **21116**.

### Вариант A — публичный VPS (белый IP)

В панели хостинга (Security Group / Firewall / «Сетевые правила») разрешите **входящие** на эти порты.

> SSH (порт **22/TCP**) не закрывайте.

### Вариант B — сервер за NAT (дом / офис / роутер)

Установщик спросит режим **«За NAT»**, локальный IP машины и публичный адрес (белый IP роутера или DDNS-домен).

На роутере настройте **Port Forwarding** (Virtual Server / «Проброс портов») на LAN IP сервера:

| Снаружи (WAN) | Протокол | Куда (LAN) |
|---------------|----------|------------|
| 21115 | TCP | `LAN-IP:21115` |
| 21116 | TCP | `LAN-IP:21116` |
| 21116 | UDP | `LAN-IP:21116` ← часто забывают |
| 21117 | TCP | `LAN-IP:21117` |
| 21118–21119 | TCP | опционально (web) |

В клиентах указывайте **публичный** IP/домен, **не** `192.168.x.x`.

После установки полный список сохранится в `/opt/rudesk/PORTS.txt`.

## Шаг 4. Скачайте rudesk и запустите установщик

От root:

```bash
cd /root
curl -fsSL https://github.com/Tuma58/rudesk/archive/refs/heads/main.tar.gz | tar xz
cd rudesk-main
bash install.sh
```

Эквивалент одной строкой:

```bash
curl -fsSL https://github.com/Tuma58/rudesk/archive/refs/heads/main.tar.gz | tar xz && bash rudesk-main/install.sh
```

Скрипт:

1. Проверит, что ОС — Debian/Ubuntu и есть systemd  
2. Выполнит `apt-get update` и поставит зависимости чистого VPS  
3. Проверит контрольные суммы бинарников из `vendor/`  
4. Задаст несколько вопросов (мастер)  
5. Установит сервисы `rudesk-hbbs` и `rudesk-hbbr`  
6. Выведет параметры для клиента и сохранит их в `/opt/rudesk/CONNECTION.txt`

---

## Шаг 5. Ответы мастера установки

### Где стоит сервер

1. **Публичный VPS** — белый IP в облаке.  
2. **За NAT / роутером** — домашний или офисный сервер. Мастер попросит LAN IP, покажет таблицу проброса портов и спросит публичный адрес для клиентов.

### Адрес сервера (для клиентов)

- Автоопределить публичный IP, или  
- Указать домен / публичный IP вручную (удобно с DDNS за NAT).

Именно этот адрес клиенты впишут в **ID server**. За NAT это адрес роутера/домена, не `192.168.…`.

### UFW

- На чистом VPS обычно **y**.  
- За NAT — по желанию (проброс на роутере обязателен в любом случае).

### Always relay

Обычно **N**. За строгим NAT сначала проверьте UDP **21116**, и только потом включайте always-relay.

В конце подтвердите установку (`y`).

## Шаг 6. Сохраните Key и проверьте сервисы

В конце установки (и в файле `/opt/rudesk/CONNECTION.txt`) будут строки вида:

```text
ID / Relay server : 203.0.113.10
Key               : длинная_строка_символов
```

**Key** — секрет сервера. Его нужно вписать в клиенты. Не публикуйте Key в открытых чатах без необходимости.

Проверка, что сервисы работают:

```bash
systemctl status rudesk-hbbs --no-pager
systemctl status rudesk-hbbr --no-pager
```

Ожидается `active (running)`.

Логи при проблемах:

```bash
journalctl -u rudesk-hbbs -u rudesk-hbbr -e --no-pager
```

Ещё раз посмотреть параметры:

```bash
cat /opt/rudesk/CONNECTION.txt
```

## Шаг 7. Настройка клиента RustDesk (на вашем ПК)

1. Скачайте клиент с [релизов RustDesk](https://github.com/rustdesk/rustdesk/releases) и установите.  
2. Откройте RustDesk → **Settings** (шестерёнка) → **Network**.  
3. Нажмите **Unlock network settings** (если есть), введите пароль разблокировки настроек.  
4. Заполните:
   - **ID server** — IP или домен с сервера (из `CONNECTION.txt`)  
   - **Relay server** — тот же адрес **или** оставьте пустым  
   - **API server** — оставьте пустым (это не Pro)  
   - **Key** — ключ из `CONNECTION.txt`  
5. Сохраните / Apply.  
6. Перезапустите клиент RustDesk.  
7. Повторите настройку Network **на каждом** устройстве, к которому будете подключаться (и с которого).

После этого ID устройств в клиенте будут регистрироваться на **вашем** сервере. Подключайтесь как обычно: введите ID удалённого ПК и пароль/подтверждение.

---

## Шаг 8. Быстрая проверка «всё ли открыто»

На своём ПК (не на VPS), если есть `nc`/`telnet`, можно проверить TCP:

```bash
nc -vz ВАШ_IP 21116
nc -vz ВАШ_IP 21117
```

Если «Connection refused» или таймаут — смотрите правила в панели хостинга и UFW:

```bash
ufw status verbose
```

## Обновление rudesk

Скачайте свежий архив **этого** репозитория и запустите `update.sh` (данные и ключ в `/var/lib/rudesk` сохраняются):

```bash
cd /root
rm -rf rudesk-main
curl -fsSL https://github.com/Tuma58/rudesk/archive/refs/heads/main.tar.gz | tar xz
bash rudesk-main/update.sh
```

---

## Удаление

```bash
bash /opt/rudesk/uninstall.sh
```

Скрипт спросит, удалять ли ключи и базу в `/var/lib/rudesk`.

---

## Что куда ставится на сервере

| Путь | Содержимое |
|------|------------|
| `/opt/rudesk/bin/` | `hbbs`, `hbbr` |
| `/opt/rudesk/CONNECTION.txt` | адрес и Key для клиентов |
| `/opt/rudesk/PORTS.txt` | порты: Security Group или проброс за NAT |
| `/opt/rudesk/rudesk.env` | параметры установки (в т.ч. режим NAT) |
| `/var/lib/rudesk/` | ключи (`id_ed25519.pub`) и данные |
| `systemd`: `rudesk-hbbs`, `rudesk-hbbr` | автозапуск |

## Частые проблемы

**«curl: command not found»**  
Сначала шаг 2: `apt-get install -y curl ca-certificates tar gzip`.

**Клиент не видит устройства / «не удаётся подключиться»**  
- Не открыты порты в панели хостинга **или** не сделан проброс на роутере (часто забывают **UDP 21116**).  
- За NAT в клиенте указан LAN IP вместо публичного адреса/домена.  
- В клиенте неверный ID server или Key (пробелы, старый Key).  
- Сервисы не запущены: `systemctl status rudesk-hbbs rudesk-hbbr`.  
- Сверьте `/opt/rudesk/PORTS.txt`.

**После включения UFW пропал SSH**  
На новом сервере зайдите через «VNC / Serial console» в панели хостинга и выполните:

```bash
ufw allow 22/tcp
ufw reload
```

Установщик старается разрешить OpenSSH до включения UFW, но если SSH у вас на нестандартном порту — разрешите его вручную заранее.

**Сменился IP у VPS**  
Обновите DNS или заново укажите новый IP во всех клиентах. Key при этом обычно тот же (лежит в `/var/lib/rudesk`). Можно поправить хост в `/opt/rudesk/rudesk.env` и `/opt/rudesk/CONNECTION.txt`.

## Для мейнтейнеров: обновление вендорных бинарников

На машине разработчика (не на пользовательском VPS):

```bash
./scripts/refresh-vendor.sh 1.1.16
```

Затем закоммитьте изменения в `vendor/`. Пользователи получат новые бинарники вместе с архивом rudesk.
